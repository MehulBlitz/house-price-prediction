# House Price Prediction — Regression & Bias-Variance Analysis

[![Retrain & refresh metrics](https://github.com/MehulBlitz/house-price-prediction/actions/workflows/update-metrics.yml/badge.svg)](https://github.com/MehulBlitz/house-price-prediction/actions/workflows/update-metrics.yml)
[![Live metrics dashboard](https://img.shields.io/badge/dashboard-MehulBlitz.github.io-2ea44f)](https://mehulblitz.github.io)

Regression on the [California Housing dataset](https://scikit-learn.org/stable/datasets/real_world.html#california-housing-dataset)
(20,640 block groups, included with scikit-learn — no download step needed)
to predict median house value from census features.

**Stack:** Python · NumPy · Pandas · Scikit-learn · Seaborn · Matplotlib · Gradio

## Results (reproduce with `python train_house.py`, seed = 42)

Held-out test set: 4,128 block groups (80/20 split). Target units are
$100k (1990 dollars).

| Model | 5-fold CV RMSE | Test RMSE | Test MAE | Test R² | Train RMSE |
|---|---|---|---|---|---|
| Linear Regression (baseline) | 0.6526 | 0.6629 | 0.4782 | 0.6646 | 0.6521 |
| Ridge (tuned) | 0.6526 | 0.6629 | 0.4782 | 0.6646 | 0.6521 |
| Lasso (tuned) | 0.6525 | 0.6629 | 0.4782 | 0.6646 | 0.6521 |
| **Random Forest (tuned)** | **0.5100** | **0.5084** | **0.3323** | **0.8028** | 0.2465 |

**Headline: test RMSE reduced by 23.3%** vs. the baseline linear model
(0.6629 → 0.5084), with R² improving 0.66 → 0.80 and MAE 0.478 → 0.332.

### Bias-variance analysis (the interesting part)

- **Learning curves** (`figures/learning_curves.png`): the linear models
  show train ≈ CV RMSE (0.652 vs 0.653) — a **bias-limited** model; more
  data would not help it. Random Forest shows a wide gap (train 0.25 vs
  CV 0.51) — a **variance-heavy** model whose curves are still converging
  as data grows.
- **Regularization was a wash — and that is a finding:** Ridge chose
  α = 100 and Lasso α = 0.0005, yet both land within rounding error of
  plain OLS. After quantile-capping the outliers and adding ratio
  features, the linear coefficients are already stable, so there was
  little left for regularization to fix; the meaningful gains came from
  switching model *class*, not from shrinking weights.
- **Overfitting control for RF:** tuning `max_depth` (20) and
  `min_samples_leaf` plus train-set-fitted quantile capping of
  AveRooms/AveBedrms/AveOccup/Population kept the forest's CV score from
  drifting away from its test score (0.5100 vs 0.5084).

Top features (`figures/feature_importance.png`): **median income
row dominates**, followed by average occupancy, location (latitude +
longitude), and the engineered bedrooms-per-room ratio.

## What this project demonstrates

- **EDA first** — target/feature distributions and a correlation heatmap
  (`figures/eda_overview.png`).
- **Outlier handling without leakage** — a custom `QuantileCapper`
  transformer (1st/99th percentile clipping) is fit **inside the
  Pipeline**, so test-fold statistics never touch training.
- **Feature engineering inside the pipeline** — rooms-per-household and
  bedrooms-per-room via a custom `FeatureEngineer` transformer.
- **Regularization compared fairly** — Linear vs Ridge vs Lasso vs Random
  Forest, tuned with `GridSearchCV` (5-fold CV on RMSE).
- **Diagnosis, not just scores** — learning curves + train-vs-CV RMSE
  table make the bias/variance story explicit and actionable.
- **Deployment** — interactive Gradio app for block-group price estimates.

## Run it

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows   (source .venv/bin/activate on macOS/Linux)
pip install -r requirements.txt

python train_house.py             # trains + tunes + saves artifacts/ and figures/
python app.py                     # interactive Gradio demo on http://127.0.0.1:7860
```

(`python app.py` auto-trains first if `artifacts/house_model.joblib` is
missing, so this is the only command you strictly need.)

(The dataset downloads automatically on first run and is cached by
scikit-learn in `~/scikit_learn_data`.)
